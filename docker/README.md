# Local Docker environment (ARBICOP)
One WordPress container mirrors production: root site at http://localhost:8082 and the shop (WooCommerce) at http://localhost:8082/tienda,
each with its own database (`arbicopc_504` prefix `wpfb_`, `arbicopc_wp847` prefix `wp1k_`). Port 8080 was taken by another project, hence 8082.
- phpMyAdmin (profile tools): http://localhost:8083. DB from host: 127.0.0.1:3308, user `wp`/`wp` (root/root).
- Start: `docker compose -p web-arbicop up -d db wordpress`. Stop: `docker compose -p web-arbicop down` (`-v` resets DB and files).
- wp-cli: `MSYS_NO_PATHCONV=1 docker compose -p web-arbicop --profile tools run --rm -T wpcli --path=/var/www/html[/tienda] <cmd>`
- `docker/gen-configs.py` regenerates `docker/wp-config.{root,tienda}.php` (git-ignored, derived from prod configs) with DB host `db`, WP_HOME local, cron off.
- WP files live in the named volume `web-arbicop_wpfiles` (copied from the project folder excluding zips, sql, logs, cache, litespeed, wp-config, .htaccess).
  `.htaccess` files in the volume are standard WP rewrites (root `/`, shop `/tienda/`).
- Local DB changes applied after import: search-replace https://arbicop.com (plain, http variant and JSON-escaped) -> http://localhost:8082;
  `_menu_item_url` made relative; `_elementor_element_cache` postmeta deleted; `wp elementor flush-css`. No plugin had to be disabled.

## Header/Footer consistency
Goal: one identical header (top bar, logo, nav) and footer on every page of the root site and of the shop (`/tienda/`).
- **Source of truth**: the header (first two top-level containers) and the footer (container holding "Enlaces") of the HOME page (post 13). `docker/header-footer/build.py` reads the pre-change dumps in `docker/backups/fix2/pre-*.json`, applies the footer edits and writes `docker/header-footer/{header,footer,footer-wrapped,shop-header,shop-footer,page-<id>}.json`. `docker/header-footer/apply.php` (`wp eval-file ... root|shop`, files copied to `wp-content/uploads/zz-fix2/`) writes them to the DB. `docker/header-footer/shot.mjs` = full-page screenshots over Chrome DevTools (Node 22+), supports 390 px mobile emulation.
- **Menu** "Menu Arbicop": Libro de Reclamaciones and Intranet were removed by setting their menu items (db ids 533, 534) to `draft` (hidden, not deleted). Result: Inicio, Nosotros, Formaciones (Peritaje, Arbitraje, Conciliacion, Tasacion, Corretaje), Beneficios, Tienda, Campus Virtual, Contacto. Backup: `docker/backups/fix2/menu-before.json`.
- **Root pages 13,15,17,19,21,23,25,27,38,341**: header + footer containers replaced by exact copies of the canonical ones (old data in `docker/backups/fix2/pre-<id>.json`). Templates 102 (header) and 502 (footer) now hold the same data.
- **Page 438** (plain Hello page, `[libro_page]` shortcode): templates 102/502 have the wrong Elementor type (section/container), so two new theme-builder templates were created, "Header Arbicop (page 438)" (id 535, type header) and "Footer Arbicop (page 438)" (id 536, type footer), with the condition `include/singular/page/438` (also in option `elementor_pro_theme_builder_conditions`). They replace the Hello header/footer on that page only.
- **Shop** (`wp1k_`): it already used Elementor theme-builder header #20 and footer #23 for all its pages (home, product, cart, checkout, my-account). Their data was replaced by `shop-header.json` / `shop-footer.json` (backup `docker/backups/fix2/shop-pre-20.json`, `shop-pre-23.json`). Differences handled: (1) Elementor globals of the root kit were resolved to explicit values (the shop kit has other colors/fonts); (2) the shop media library has no attachment 452, so the logo uses the same file's Elementor crop by site-relative URL; (3) nav font pinned to DM Sans; (4) the shop menu "Menu Arbicop" (same items, relative URLs, without Libro/Intranet) was created in the shop DB; (5) mu-plugin `tienda/wp-content/mu-plugins/arbicop-shared-header.php` re-declares the root kit variables (container width 1340, padding 0, widget spacing 0) scoped to `.elementor-location-header/footer`, so shop pages are untouched. Trade-off: the shop's own header cart icon / "Aula Virtual" button are gone (cart still at `/tienda/cart/`).
- **Logo**: single file = attachment 452 `uploads/2026/06/cropped-LOGO-ARBICOP.png`, Elementor custom crop 300x88 (the home header logo). Hello theme `custom_logo` of the root site changed 454 (jpeg) -> 452 (`docker/backups/fix2/theme-mod-custom-logo.txt`). Footer keeps the white variant (attachment 483) because the footer is dark.

- Still absolute: Elementor emits `http://localhost:8082/wp-content/uploads/...` for attachment images (incl. logo) on root pages; links we control are relative (the shop copies use site-relative image urls).

## Shop cart icon
The shop header (template #20, same as the root header) has a cart icon again, shop pages only (root site untouched).
- **Code**: `tienda/wp-content/mu-plugins/arbicop-shop-cart.php`: shortcode `[arbicop_cart]` (cart link `/tienda/cart/` made relative, SVG bag, count badge, subtotal on desktop >=1024 px; on mobile only icon+badge, right of the hamburger), its CSS (navy `#030D67`, badge `#2B9BE8`, DM Sans; header height unchanged: 174 desktop / 104 mobile), and `wp_enqueue_script('wc-cart-fragments')` (WooCommerce 11 does not load it on every page any more).
- **Header wiring**: `docker/header-footer/build.py` appends an Elementor `shortcode` widget (`[arbicop_cart]`, id a1c0c4a7) after the nav-menu in the shop header; apply with `apply.php shop` (as above; the mu-plugin must be `docker cp`ed into the wpfiles volume: `tienda/wp-content/mu-plugins/`, then `apachectl -k graceful` because of opcache).
- **Live update**: server renders the current count on every page; ajax add-to-cart returns the fragment `a.arbicop-cart` (filter `woocommerce_add_to_cart_fragments`) and `wc-cart-fragments` swaps it in without reload (also `wc_fragment_refresh`). Works on cart, checkout, my-account (no Elementor side-cart panel: the click goes straight to the cart page).
- The pro `woocommerce-menu-cart` widget was not used: its side-cart panel replaces the plain link and it pulls its own scripts. Backups: `docker/backups/cart/`.
- Verification (2026-11-20, local, no payment): screenshots `docker/screenshots/cart-*-{1440,390}.png`.
- Known (pre-existing, not from this change): `/tienda/checkout/order-received/<id>/` with a non-existent order fatals in `woo-micuentaweb-payment` (line ~2025); the order-received page with a real order was not tested.

## Static clone (phase 3)
The root site is cloned to `src/` -> `dist/` (see the root `README.md`). Importer: `tools/wp-import.mjs` (reads this local WordPress at :8082).
Preview of `dist/` with production-like Apache: `docker compose -f docker-compose.static.yml -p arbicop-static up -d --build` (http://localhost:8084).
Pixel diff vs this WordPress: `npm run compare` -> `docker/screenshots/static-*.png`, summary `docker/screenshots/static-diff.md`; interaction checks: `node tools/interact-check.mjs`.
Static header/footer differ from WordPress only by design: no hidden leftovers (old header buttons, hidden Libro bar), `/libro-de-reclamaciones-2/` links point to `/libro-de-reclamaciones/`, no cart icon (shop only).
